Deux charts sont publiés en OCI : `oci://ghcr.io/batleforc/proxyauthk8s/chart-crd` (les CRD)
et `oci://ghcr.io/batleforc/proxyauthk8s/chart` (l'application). Le [Quick Started](/docs/quick-started) montre une
installation complète ; cette page décrit les values. Le fichier de référence est
`deploy/chart/values.yaml`, et le chart embarque un `values.schema.json` : Helm refuse une
clé inconnue (faute de frappe) ou une valeur mal typée avant de rendre quoi que ce soit.

Les charts publiés sont signés avec cosign (keyless) :

```bash
cosign verify ghcr.io/batleforc/proxyauthk8s/chart:<version> \
  --certificate-identity-regexp 'https://github.com/batleforc/.*' \
  --certificate-oidc-issuer https://token.actions.githubusercontent.com
```

```bash
cosign verify ghcr.io/batleforc/proxyauthk8s/server:<version> \
  --certificate-identity-regexp 'https://github.com/batleforc/.*' \
  --certificate-oidc-issuer https://token.actions.githubusercontent.com
```

Les attestations de provenance et de SBOM se vérifient par digest :

```bash
gh attestation verify oci://ghcr.io/batleforc/proxyauthk8s/server@<digest> \
  --repo batleforc/ProxyAuthK8S
```

## Exposition

| Value                     | Défaut               | Description                                              |
| ------------------------- | -------------------- | -------------------------------------------------------- |
| `ingress.enabled`         | `true`               | Crée l'Ingress (`/` → front, `/api/` et `/clusters/` → back) |
| `ingress.className`       | `""`                 | IngressClass                                             |
| `ingress.annotations`     | `{}`                 | Annotations (cert-manager, timeouts de l'ingress...)     |
| `ingress.host`            | `proxyauthk8s.local` | Host public : base des redirect URIs et origine CORS par défaut |
| `ingress.apiHost`         | `""`                 | Second host qui ne sert que les clusters (`/clusters/…`), pour `oc login --web` ; même secret TLS |
| `ingress.tls.enabled`     | `true`               | TLS sur l'Ingress                                        |
| `ingress.tls.secretName`  | `proxyauthk8s-tls`   | Secret TLS                                               |

<Callout type="warn">
Les flux `watch`, `exec` et `logs -f` passent par l'Ingress : augmentez ses timeouts de
lecture (ex. `nginx.ingress.kubernetes.io/proxy-read-timeout: "3600"`), sinon l'ingress coupe
les connexions longues.
</Callout>

## OIDC

| Value                      | Défaut                   | Description                                                         |
| -------------------------- | ------------------------ | ------------------------------------------------------------------- |
| `oidc.source`              | `secret`                 | `secret` (recommandé) ou `env`                                      |
| `oidc.objectName`          | `proxyauthk8s-back-oidc` | Secret lu en `envFrom` par le back (`OIDC_ISSUER_URL`, `OIDC_CLIENT_ID`, `OIDC_CLIENT_SECRET`, `OIDC_SCOPES`, `OIDC_AUDIENCE`) ; le front n'en lit que les clés publiques |

toute personne pouvant lire les Deployments le voit. Préférez `secret`.
</Callout>

## Passerelle d'agents

Les values `agentGateway.*` (passerelle des clusters joints par un agent, RFC 0012) sont
décrites avec leur contexte dans [Agent](/docs/agent#1-activer-la-passerelle).

## Disponibilité : PDB, HPA et GitOps

Le back, le front et la passerelle d'agents (`agentGateway`, mode `separate`) suivent les
mêmes règles :

- **PDB** (`podDisruptionBudget.*`) : `minAvailable: 1` par défaut. Un `maxUnavailable`
  défini le remplace (l'API refuse les deux), `0` compris ; une valeur vide est ignorée.
  Avec un seul pod au minimum (`replicas`/`replicaCount`, ou `autoscaling.minReplicas`
  avec l'HPA), le chart rend `maxUnavailable: 1` : un `minAvailable: 1` bloquerait tout
  `kubectl drain`, et le PDB protège encore les pods quand l'HPA monte.
- **HPA** (`autoscaling.enabled`) : le chart reprend le nombre de pods en place (`lookup`)
  à chaque `helm upgrade`, sans écraser le choix de l'HPA ni retirer le champ (Helm
  retomberait alors à 1 pod). Sans Deployment à lire (première installation,
  `helm template`, `--dry-run`, Argo CD), il rend `autoscaling.minReplicas`.
- **Réduction lente** des pods qui portent des tunnels d'agents : chaque pod retiré ferme
  ses tunnels, et ses agents se reconnectent. L'HPA de la passerelle, et celui du back en
  mode `embedded`, attendent `agentGateway.autoscaling.scaleDownStabilizationSeconds`
  (600 s) puis retirent `scaleDownPods` pod(s) par `scaleDownPeriodSeconds` (300 s).

<Callout type="warn" title="Argo CD et l'HPA">
Argo CD rend le chart sans accès au cluster : `lookup` n'y renvoie rien, et chaque
synchronisation remettrait `replicas` à `autoscaling.minReplicas`, contre l'HPA. Laissez ce
champ à l'HPA :

```yaml
apiVersion: argoproj.io/v1alpha1
kind: Application
spec:
  ignoreDifferences:
    - group: apps
      kind: Deployment
      jsonPointers:
        - /spec/replicas
  syncPolicy:
    syncOptions:
      - RespectIgnoreDifferences=true   # sinon la synchro applique quand même le champ
```

Flux (`helm-controller`) exécute un vrai `helm upgrade` : `lookup` y fonctionne, rien à faire.
</Callout>

## RBAC

| Value                        | Défaut | Description |
| ---------------------------- | ------ | ----------- |
| `rbac.referencedNamespaces`  | `[]`   | Namespaces dont les Secrets / ConfigMaps / Services peuvent être référencés par un `ProxyKubeApi`. Vide = `get` cluster-wide ; renseigné = un `Role` par namespace (moindre privilège) |

Le compte de service reçoit toujours : lecture des CRD, lecture/mise à jour des
`ProxyKubeApi` (statut, finalizers), `create`/`patch` sur les `events.k8s.io` (les
[Events](/docs/status-and-events) publiés sur chaque `ProxyKubeApi`), et `get`/`create`/`update`/`patch`
sur les `leases` de son propre namespace pour l'élection de leader.

<Callout type="warn">
Depuis la 0.4.0, le leader libère son lease à l'arrêt. Pour revenir à une version
antérieure, supprimez d'abord le lease, que l'ancienne élection ne saurait plus reprendre :
`kubectl -n <namespace> delete lease proxy-auth-k8s-leader-election`.
</Callout>

## Sécurité des pods

`securityContext.pod` et `securityContext.container` s'appliquent au back, au front et au
collecteur OTel : utilisateur non-root (`1000`), système de fichiers racine en lecture seule,
toutes les capabilities retirées, profil seccomp `RuntimeDefault`.

## NetworkPolicy

| Value                                   | Défaut  | Description                                                        |
| --------------------------------------- | ------- | ------------------------------------------------------------------ |
| `networkPolicy.enabled`                 | `false` | Active les NetworkPolicies du front, du back et de la passerelle d'agents |
| `networkPolicy.ingressFrom`             | `[]`    | Sélecteurs autorisés à joindre les services (ex. le namespace de l'ingress controller) ; vide = tout le cluster |
| `networkPolicy.egress.allowExternal`    | `true`  | Autorise la sortie vers l'extérieur du cluster (apiservers, IdP)   |
| `networkPolicy.egress.externalExcept`   | plages privées, link-local, CGNAT | Exclues de la sortie externe : bloque notamment l'endpoint de métadonnées cloud |
| `networkPolicy.egress.extra`            | `[]`    | Règles d'egress supplémentaires (Redis, apiservers internes...)    |

<Callout type="info">
Désactivée par défaut car le chart ne peut pas deviner où sont Redis et les clusters cibles.
En production, activez-la et décrivez ces destinations dans `egress.extra`.
</Callout>
